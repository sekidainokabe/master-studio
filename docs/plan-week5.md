# 第5週 作業計画（サーバー側横断検証、CSV 取り込み、差分）※承認済み（2026-11-12）・完了

第4週が11/11に終わったため、前倒しで進める。

## 決めたいこと

- **横断検証は「変更セットを反映したあとの全マスタ」を対象にする**
  - 4つのマスタの本番データに変更セットの変更を重ねたもの（約210行）を1回ずつまとめて読み込み、メモリ上で確かめる。行ごとに SQL を発行しない
  - 単一セルの検証と違い、他のマスタや他の行を見る必要があるので、サーバーだけで行う（SPEC 5章）
  - エラーは保存を止めない（第4週と同じ）。止めるのはレビュー依頼・承認のとき（第6週）
- **ルールの分け方**
  - スキーマから決まる共通ルール：参照先があるか、削除する行が参照されていないか。どのマスタにも効く
  - ゲーム固有のルール：敵配置の座標、ステージごとのボス数、解放条件の循環。1ルール1クラスにして、共通のインターフェースで並べる（ルールを足すときに既存のコードを触らずに済む）
  - record_key の一意性は、DB の一意制約（changeset_id, master_table_id, record_key）と重ね方の仕組みで保証されるため、ルールとしては持たず、テストで確かめる
- **CSV 取り込みは「追加と更新だけ」**
  - CSV にない行は消さない。消すつもりのない行が、CSV の書き漏れで消える事故を防ぐため。削除は画面で行う
  - 1行目は見出し（`record_key` と列の key）。列の順番は自由で、一部の列だけでもよい（ない列は今の値のまま）
  - 文字コードは UTF-8（BOM あり・なし）と Shift_JIS を受け付ける。日本語の Excel で保存した CSV が Shift_JIS になることが多いため
  - 型が合わない値（数値の列に文字など）も取り込み、エラーとして表示する（第4週と同じ考え方）。見出しに知らない列がある、record_key の形式が違う、500行を超える、などデータとして扱えないものは 422 で全体を拒否する
  - 取り込みと対になる **CSV のダウンロード**（編集中のデータ）も作る。形式を説明しなくても、ダウンロード → Excel で編集 → 取り込み、で使えるようにするため
- **差分は「今の本番」と比べる**
  - 承認者が見たいのは「承認したら本番がどう変わるか」なので、変更セット作成時点ではなく今の本番と比べる
  - 作成後に本番が変わっていた場合の競合の検出は、第6週（承認処理）で行う

## 作業手順

### ステップ1：横断検証（サーバー）

- `app/Validation/CrossValidator.php` と、ルールごとのクラス（`app/Validation/Rules/`）
  - 参照先の存在（同じ変更セットで追加した行は認め、削除する行は認めない）
  - 参照されている行の削除禁止
  - 敵配置の座標がステージの width / height の範囲内
  - 1ステージにボス（rank=boss の敵の配置）は1体まで
  - unlock_stage_id が自分自身でない、解放条件が循環していない
- `GET /api/changesets/{id}/validation`：単一セルと横断のエラーをまとめて返す。各エラーは `{master, record_key, column, kind: cell|cross, message}` と件数
- PHPUnit：ルールごとに、エラーになる例とならない例。本番のシードデータはエラー0件であること。SQL の発行回数がマスタの数に比例し、行数に比例しないこと

### ステップ2：編集画面に検証結果を出す

- 表の上に「検証結果」パネル。エラーの一覧で、押すとそのマスタのタブに移ってその行までスクロールする
- 横断のエラーもセルを赤くする（参照切れの敵の ability_id など）。単一セルのエラーは今までどおり画面でその場で出し、横断のエラーは保存のあとに取り直す
- Vitest：検証結果をセルごとのエラーに振り分ける関数

### ステップ3：差分

- `GET /api/changesets/{id}/diff`：マスタごとに、追加・削除・変更の行と、変更した列の「前 → 後」
- 変更セット詳細画面に差分を表示する（追加 = 緑、削除 = 赤、変更したセル = 黄で「前 → 後」）と、検証結果の件数
- PHPUnit：追加・更新・削除の形、変更のない列は含めないこと

### ステップ4：CSV の取り込みとダウンロード（サーバー）

- `POST /api/changesets/{id}/masters/{key}/import`（ファイルは1MB・500行まで）。読み込んだあとは、第4週の一括保存（`ChangesetRecords::save`）に渡す。結果は追加・更新・変化なしの件数
- `GET /api/changesets/{id}/masters/{key}/export`：編集中のデータを CSV で返す（Excel で開けるよう BOM 付き UTF-8）
- 権限は一括保存と同じ（403 / 409）
- PHPUnit：UTF-8・BOM・Shift_JIS、型の変換（数値、はい/いいえ・true/false・1/0、空欄は null）、一部の列だけの CSV、知らない列や壊れた CSV は 422 で何も保存しないこと、ダウンロード → 取り込みで変化なしになること

### ステップ5：CSV の画面

- 編集画面に「CSV をダウンロード」「CSV を取り込む」。取り込みの結果（追加 N 件・更新 N 件）と、422 のときは理由を表示する
- 未保存の編集があるときは取り込めないようにする（どちらを優先するかで迷わせないため）

### ステップ6：確認と仕上げ

- ブラウザで、参照切れ・ボス2体・ステージ外の配置を作ってエラーが出ること、Excel 形式（Shift_JIS）の CSV を取り込めること、差分の表示を確かめる
- CLAUDE.md の進捗を更新する。本番へのデプロイ（第4〜5週の分）をするか相談する

## 範囲外

- 作成後に本番が変わっていたときの競合検出：第6週
- デモ用の変更セット（わざとエラーを含める）のシード：第6週
- CSV での行の削除
