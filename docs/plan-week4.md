# 第4週 作業計画（編集画面、一括保存、フロント側単一セル検証）※承認済み（2026-11-05）

## 決めたこと

- **エラーがあっても保存できる**
  - 型・範囲・必須などのルール違反は、保存したうえでエラーとして返す
  - 存在しない列名や、record_key の形式違反のように、データとして扱えない入力は 422 で拒否する
  - ルール違反のあるデータが本番に入るのは、レビュー依頼・承認のときに止める（第6週）
  - 理由：SPEC 11章のデモは、エラー入りの変更セットを開いて赤いセルを見せる筋書きのため。保存のたびに拒否すると、下書きを途中で保存できない
- **編集用の表は TanStack Table**
  - 見た目を持たず、表の状態（列や行）の管理だけを行うライブラリ。描画は自前の `<table>` で行い、エラーセルの表示を自由に作れる
  - 最大150件ほどなので、仮想スクロールは使わない

## 作業手順

### ステップ1：単一セル検証のルール（PHP と TypeScript）

- 型、必須、数値範囲、文字数、列挙値を確かめる関数を、同じルールでフロント（`lib/validation.ts`）とサーバー（`app/Validation/CellValidator.php`）に作る。フロントは入力してすぐに結果を出すため、サーバーは最終的に判定するため
- 2つの実装の結果がずれないよう、テストに同じ例を入れる
- テスト：Vitest と PHPUnit

### ステップ2：編集用データの API

- `GET /api/changesets/{id}/masters/{key}/records`：本番データに変更セットの変更を重ねて返す。各行に「変更なし / 追加 / 変更 / 削除」の状態と、検証エラーを付ける
- `PUT` 同じパス：複数行の追加・更新・削除を、1つのトランザクションでまとめて保存する
  - 本番と同じ値に戻した行は、変更の記録（changeset_items）を消す
  - 変更セットの中で追加した行を削除したときも、記録を消す
- `DELETE /api/changesets/{id}/items/{itemId}`：変更を1件ずつ取り消す
- 権限（Policy に `update` を追加）
  - editor は自分の変更セットだけ、admin はすべてを編集できる
  - 編集できるのは draft のときだけ。それ以外の状態では 409 を返す
- PHPUnit：重ねたデータの形、追加・更新・削除・元に戻す、他人と approver は 403、draft 以外は 409、データとして扱えない入力は 422

### ステップ3：変更セットの編集・削除（`PATCH` / `DELETE /api/changesets/{id}`、draft のみ）

- 詳細画面に「データを編集」「タイトルを編集」「削除」のボタンを付ける。権限がない人には表示しない
- PHPUnit：権限と状態

### ステップ4：編集画面の表示（`/changesets/:id/edit`）

- マスタごとのタブ。選んでいるタブは URL（`?master=enemies`）に持たせる
- TanStack Table で表を作り、行の状態で色を分ける（追加 = 緑、削除 = 取り消し線）
- 参照列の選択肢には、変更セットの中で追加した行も含める（SPEC 5章）

### ステップ5：セルの編集と一括保存

- 型に応じた入力欄（数値、文字、チェックボックス、列挙値と参照はプルダウン）。行の追加と削除
- 入力したらすぐに検証し、エラーのセルは赤くして、ホバーで理由を表示する
- 「未保存の変更が N 件」の表示と保存ボタン。保存しないままページを離れようとしたら確認を出す（React Router の `useBlocker`）
- Vitest：編集内容から PUT で送るデータを組み立てる関数

### ステップ6：確認と仕上げ

- ブラウザで、editor で編集 → 保存 → 再読み込みしても残っている、エラーのセルが表示される、approver と他人の変更セットでは編集できない、を確かめる
- CLAUDE.md の進捗を更新する

## 範囲外

- 横断検証、CSV の取り込み、差分の画面：第5週
- レビュー依頼・承認：第6週
- 同じ変更セットを2つのタブで同時に編集したときの競合：扱わない（後から保存した方が勝つ）
