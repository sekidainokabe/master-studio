## 作業手順

### ステップ1：マスタの API

- `GET /api/masters`：一覧と件数・最終更新日時。件数をマスタごとに数えると SQL がマスタの数だけ発行される（N+1 問題）ため、`withCount` / `withMax` で1回の SQL にまとめる
- `GET /api/masters/{key}/schema`：列定義。参照先マスタは id ではなく `key` で返す（画面側で id を意識しなくて済むように）
- `GET /api/masters/{key}/records`：本番データ
- URL の `{key}` からマスタを取り出すルートモデルバインディングを使う（存在しない key は自動で 404）
- 返す形は API Resource で決める
- PHPUnit：形、件数、存在しないマスタの 404、未ログインの 401

### ステップ2：変更セットの API（作成・一覧・詳細）

- `GET /api/changesets`：状態・作成者で絞り込み、20件ずつのページ分け
- `POST /api/changesets`：タイトル（必須、200文字以内）と説明。作成者はログイン中のユーザー、状態は draft、作成時点の最新リリースを `base_release_id` に記録
- `GET /api/changesets/{id}`：基本情報のみ（編集画面はまだないため）
- 権限：SPEC では作成できるのは editor と admin。ここだけ Policy で先に入れる（承認・却下などは第6週）
- PHPUnit：作成、入力チェック、approver は作成できない（403）、絞り込み、ページ分け

### ステップ3：マスタ一覧・閲覧の画面

- `/masters`：マスタ一覧（名前、件数、最終更新日時）
- `/masters/:key`：読み取り専用の表。列は API の列定義から組み立てる（マスタが増えても同じ画面で表示できる）
  - 参照列は「ab_001 体当たり」のように参照先の名前も表示
  - キーワード検索と、列挙型の列ごとの絞り込み
  - 「変更セットを作成」へのリンク
- 検索・絞り込みはブラウザ側で行う（データは最大150件ほどで、通信なしで反応が速いため。大きくなったらサーバー側に切り替える）
- 表はライブラリを使わず `<table>` で作る（編集用の表のライブラリは第4週で決める）
- ヘッダーに各画面へのナビゲーション
- Vitest：検索・絞り込みの関数のテスト

### ステップ4：変更セットの一覧・作成の画面

- `/changesets`：一覧（状態、「自分のもの / すべて」で絞り込み、ページ送り）
- 作成フォーム → 作成後に `/changesets/:id`（今週は基本情報の表示のみ。差分などは第5〜6週）
- approver では作成ボタンを表示しない（サーバー側の 403 と二重に守る）
- 確認：ブラウザで editor の作成〜一覧・詳細、approver で作成ボタンが出ないこと
